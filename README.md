# Web Publish Tool

一个基于 Electron 的桌面工具。发送端可以管理多个项目，每次操作只处理所选项目。

| 项目类型 | 项目卡操作 | 结果 |
| --- | --- | --- |
| 部署项目 | 本地打包 | 在发送端生成构建产物 ZIP，并打开保存目录 |
| 部署项目 | 部署 | 构建并上传该项目，接收端将产物部署到指定的 Cloudflare Pages 项目和分支 |
| 源码项目 | 本地打包 | 在发送端生成源码 ZIP，并打开保存目录 |
| 源码项目 | 打包并发送 | 在发送端保存源码 ZIP，接收端将同一份源码解压到指定目录下的新版本目录 |

## 功能概览

### 发送端功能

- **多项目管理**。点击「创建项目」时选择「部署项目」或「源码项目」。两类项目共用「本地构建配置」，各自保存项目名称、本地目录、Git 分支和 ZIP 输出目录。部署项目还需填写构建命令和构建产物目录。
- **Git 分支检查与同步**。两类项目都可以选择、刷新本地分支。打包时会核对所选分支，分支不符时可点击「切换并同步」再打包。普通文件夹也可作为源码项目，直接打包当前工作目录。
- **本地打包**。部署项目执行构建命令并压缩构建产物，源码项目直接压缩当前工作区。两类项目均可单独打包并打开 ZIP 保存目录，默认保存在项目的 `.web-publisher-artifacts/` 下。
- **单项目部署**。点击「部署」会重新构建并打包，再分片上传。发送端显示构建与上传日志，提交后自动查询远程任务状态，展示部署地址或失败原因。同一份 ZIP 再次上传到同一目标时，可跳过已接收的分片。
- **发送源码**。在「源码项目」中打开对应的项目卡。发送内容包括工作区内符合筛选规则的未提交改动和新文件。接收端确认解压后，日志显示「发送完成」和实际版本目录，可复制路径。失败时日志显示原因，有待重试任务时可点击「继续原任务」。

### 接收端功能

- **服务管理**。可启动和停止接收服务，设置监听地址、端口、鉴权 Token、工作目录、Cloudflare 凭据和 Wrangler 命令。以接收端或双端模式启动应用时，接收服务会自动启动。
- **构建产物接收与校验**。部署接口可接收完整 ZIP 或分片上传。分片上传会校验各分片的 SHA-256，合并后再核对整包大小和 SHA-256，通过校验后创建部署任务。
- **排队部署**。接收端按顺序处理任务，检查 ZIP 内的文件路径，解压后调用 Wrangler 部署到指定 Pages 项目和分支。首次创建 Pages 项目时，会将本次指定的部署分支设为生产分支。
- **任务列表与日志**。可查看项目、分支、创建时间和任务状态（排队中、部署中、成功、失败），展开部署日志，查看失败原因或从 Wrangler 输出中提取的 `pages.dev` 地址。任务列表和日志仅保留在当前应用进程内，退出应用后无法在界面回看。
- **源码接收目录**。可为本机目录设置名称，供发送端选择。每次主动发送都会在所选目录下新建一个项目版本，完成校验和解压后写入源码接收记录。可从记录打开对应的版本目录。

### 通用功能

- **运行模式**。`Sender` 可打包、部署或发送源码。`Receiver` 在同一地址和端口按接口分别处理构建产物和源码。`Both` 可在同一台机器上使用两端功能。
- **配置保存与迁移**。支持在本机保存设置、导出和导入 JSON 配置，也兼容旧版单项目配置。导入会覆盖当前设置，导出文件会包含已填写的接收端 Token 和 Cloudflare API Token。
- **通信鉴权**。发送端上传构建产物、查询部署状态、获取源码接收目录和发送源码时，均使用 Bearer Token 向接收端验证身份。


## 运行环境

- 从源码开发时需要 Node.js 和 npm 或 pnpm。本项目已在 Node.js 22.16 下验证。
- macOS / Windows / Linux
- 部署项目的发送端需要 Git、`zip` 和项目构建命令所需的工具。接收端部署到 Cloudflare Pages 时需要 `unzip` 和可用的 Wrangler。
- 源码打包使用应用内置的 Electron / Node.js 运行时。文件筛选与 ZIP 写入实现在 `desktop/src/services/source-pack/`，换机器后无需安装 Python 或复制 Finder 快捷操作。

## 基本使用流程

### 从发送端打包与部署

1. 点击「创建项目」，选择「部署项目」并填写项目名称，再选择本地 Git 仓库和构建分支。
2. 配置构建命令与构建产物目录。只需 ZIP 时，点击「本地打包」即可。
3. 如需发布，填写接收端地址与鉴权 Token、Cloudflare Pages 项目名和部署分支，再点击「部署」。

### 在接收端部署构建产物

1. 在「接收端服务」中打开「产物部署」，配置监听地址、端口和鉴权 Token
2. 配置 Cloudflare `API Token`、`Account ID`、`wrangler` 路径
3. 启动接收服务
4. 通过任务列表查看部署状态、日志和结果

### 发送一份源码

1. 在「接收端服务」中打开「源码接收」，选择本机文件夹、填写名称并保存配置，启动接收服务。旁边的「产物部署」可查看 Cloudflare Pages 部署记录。
2. 在发送端点击「创建项目」，选择「源码项目」并填写名称。在展开的「本地构建配置」选择项目路径、Git 分支和打包产物输出目录。点击「本地打包」即可在本机取得 ZIP。
3. 需要发送时，在同一张卡的「远端接收配置」填写接收端地址和鉴权 Token，点击「刷新目录」，选择接收目录，再点击「打包并发送」。两种操作都用发送端本地时间命名源码包，例如 `我的项目_source_20261114_143005.zip`。同一目录里发生重名时，依次追加 `-2`、`-3`。
4. 两端更新后，接收端按 ZIP 文件名中的时间解压，例如 `我的项目_source_20261114_143005.zip` 会解压到 `<接收目录>/我的项目/20261114_143005/`。远端目录重名时自动追加序号。发送端显示实际路径，接收端可从记录打开目录。失败后点击「继续原任务」，即使工作区已改动或本地 ZIP 已移动，也会续传原快照。

打包沿用 macOS Finder「项目打包」的文件筛选方式：使用源码根目录的 `.gitignore`，始终跳过 `.git`，保留遍历到的 `.gitignore` 文件。子目录中的规则不会单独加载。缺少根 `.gitignore` 时，本地环境文件和依赖目录也可能被发送。ZIP 内保留项目相对路径，接收后可直接在版本目录中看到项目文件。

升级时，普通旧项目归入「部署项目」，原有的专用源码项目归入「源码项目」。已选过源码接收目录或有待重试源码任务的旧部署项目会拆成两个独立项目，源码项目保留原任务标识以便续传。

## 配置说明

应用会将运行配置保存到 Electron `userData` 目录下的 `config.json`，不在仓库内。

默认配置包括：

- 接收端默认地址：`http://127.0.0.1:17777`
- 默认鉴权占位值：`change-me`
- 默认工作模式：`sender`

公开仓库前请不要提交任何实际 Token、账号、私钥或本地配置文件。

## 安全说明

- 当前仓库中的敏感字段示例均为占位值，不应替换为真实凭证后再提交
- 建议仅为 Cloudflare 创建最小权限 API Token
- 如果需要公网访问接收端，建议配合 HTTPS、Cloudflare Tunnel 或内网/VPN 使用
- 请确保 `.env`、本地产物、缓存文件和个人配置均被 `.gitignore` 排除
